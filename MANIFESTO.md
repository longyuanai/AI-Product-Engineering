## Product Before Code

We optimize for shipped products that solve real problems, not for volume of code. Every line of code should trace back to a user need, a hypothesis, or a validated requirement.

## Evidence Over Opinion

Decisions cite sources. We distinguish clearly between evidence (data, citations, experiments) and opinion (beliefs, intuitions, conventions). Unverified claims do not become standards.

## Validation Before Implementation

We validate before we build. Discovery, research, and validation are not optional phases. The cheapest learning happens before any code is written.

## Reuse Before Reinvent

We prefer existing standards, protocols, libraries, and patterns when they fit. APES explicitly does not replace general product management or engineering-quality frameworks — it composes with them.

## Iteration Over Perfection

We ship small, learn from reality, and revise. A useful draft today is worth more than a perfect document next year. Each version of APES reflects what has actually been learned, not what is theoretically best.

## How to Use This Manifesto

These principles guide conflict resolution. When a process decision is ambiguous, return to these five principles and explain which one supports the chosen direction.
